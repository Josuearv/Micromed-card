## Decisiones para probar

- En un turno nuevo, persistir el resultado estable antes de animar permite restaurar directamente la siguiente decisión, el resumen o el resultado terminal, según corresponda. Hacer explícita la transición terminal que borra el guardado o conserva un resultado recuperable. Confirmar la UX del mensaje que indica qué frontera se recuperó.
- Un guardado V3 intermedio en `TURNO_RIVAL` carece de cursor fiable. Dar prioridad a un respaldo anterior estable que corresponda a la misma sesión. Un respaldo también intermedio no demuestra continuidad. Cuando ambas copias carezcan de una frontera demostrable, presentar el estado como no reanudable y conservar los datos para recuperación, con reinicio mediante confirmación.
- Asegurar consistencia entre `run.playerLp` y `duelState.playerLp` según la fase y el resumen. La recuperación parcial en infinito permite una diferencia legítima durante la pantalla de recompensas. El contrato debe reflejarla.
- Un fallo de guardado durante una resolución deja la sesión viva en memoria con un estado visible de progreso sin guardar y un último checkpoint verificable. Probar reintento idempotente y acciones rápidas cuando el usuario cambia de partida.
- Mantener cualquier prueba visual con el catálogo real de `medicalCards.ts`, `organs.ts` y `outbreaks.ts`. Los recursos futuros siguen CV-ART-01 v1.0 y la aprobación humana de las referencias piloto de UX-V4-02.
